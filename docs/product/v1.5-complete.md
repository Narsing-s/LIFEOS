# LIFEOS V1.5 Complete Expansion

This milestone closes the major V1 gaps without weakening the privacy-first model.

## Domains

- Integrations: Google OAuth, Photos, Drive, Calendar, Gmail and Contacts; provider-neutral adapter layer.
- Timeline: normalized life events with time, source, location, people and links to LIFEOS records.
- Memory engine: extraction, deduplication, confidence, importance, temporal context and graph relationships.
- Knowledge graph: entities and typed relationships across people, places, events, documents, tasks, assets and expenses.
- Universal inbox: normalized incoming items with classification and action state.
- Finance: income, expenses, subscriptions, budgets, recurring payments, receipts and goals.
- Planning: calendar-aware daily/weekly planning, conflicts, preparation checklists and reminders.
- Notifications: in-app, email and push channels with preferences and delivery history.
- Automation: user-owned rules with explicit triggers, conditions and actions; no unrestricted autonomous execution.
- Mobile: Expo/React Native client with offline queue and synchronization contracts.
- Offline: local cache, mutation queue, idempotency keys and conflict policy.
- Security: refresh-token rotation, device/session management, passkeys/2FA hooks, encryption boundaries, audit events, rate limits and upload scanning hooks.
- Observability: request IDs, structured logs, health/readiness, metrics and AI usage accounting.
- AI: provider abstraction, model policy, usage limits, retrieval citations, action approval and prompt/version tracking.
- Public API: versioned OpenAPI surface and scoped integration/plugin contracts.

## Privacy rules

1. OAuth tokens are encrypted at rest and never returned to clients.
2. Every integration connection belongs to exactly one user.
3. Imported records retain source/provider IDs and timestamps.
4. AI retrieval is always authorization-first and user-scoped.
5. External actions require explicit user authorization and are auditable.
6. Sync jobs are idempotent and resumable.
7. Users can disconnect a provider and request deletion of imported data.

## Sync pipeline

`OAuth -> encrypted connection -> cursor-based sync -> normalize -> deduplicate -> timeline -> memory/entity extraction -> search index -> notifications`

## AI pipeline

`question -> intent -> authorization -> hybrid retrieval -> graph expansion -> context budget -> provider -> citations -> optional approved action -> audit`

## Offline pipeline

`UI mutation -> local store -> idempotency key -> sync queue -> API -> conflict check -> commit -> acknowledgement -> local reconciliation`

## Acceptance bar

All new domains must have authenticated API tests, authorization tests, failure-path tests, deterministic fixtures and browser/mobile smoke coverage before being considered complete.
